# Подпись кода и предупреждение Windows при установке

## Главное, без иллюзий

**Способа мгновенно убрать предупреждение SmartScreen нет.** Никакой сертификат — даже самый
дорогой — не снимает его сразу. SmartScreen проверяет не подпись, а **репутацию**: видела ли
Windows, что этот файл массово скачивают и он не вредит. У свежего билда репутации нет по
определению. Сайты, обещающие «мгновенный обход SmartScreen», продают то, чего с августа 2024
не существует.

Есть два разных предупреждения, их часто путают:

1. **«Издатель неизвестен»** (в окне контроля учётных записей) — снимается любым валидным
   сертификатом от доверенного центра **сразу**: в диалоге появляется ваше имя.
2. **«Система Windows защитила ваш компьютер» / SmartScreen** — про репутацию скачиваний, а не про
   подпись. Подпись только *привязывает* репутацию к вашему имени, чтобы она накапливалась от
   выпуска к выпуску.

Ключевое изменение: **с августа 2024 Microsoft убрала мгновенную репутацию у EV-сертификатов.**
Раньше EV снимал SmartScreen сразу — теперь EV и обычный OV набирают репутацию одинаково.
Переплачивать за EV ради снятия предупреждения больше нет смысла.

## Требования к сертификату

Из документации Microsoft
([Code signing for Smart App Control](https://learn.microsoft.com/ru-ru/windows/apps/develop/smart-app-control/code-signing-for-smart-app-control)):

- сертификат должен быть **RSA** — подписи на эллиптических кривых (ECC) Smart App Control не принимает;
- сертификат должен быть выдан **доверенным поставщиком**; самоподписанный годится только для
  внутреннего использования;
- подпись делается `signtool.exe` из Windows SDK:
  `sign /fd SHA256 /tr <RFC3161> /td SHA256`
  ([инструкция Microsoft](https://learn.microsoft.com/ru-ru/windows/win32/appxpkg/how-to-sign-a-package-using-signtool)).

## Варианты, по эффективности

| Способ | Убирает SmartScreen | Кому подходит |
|---|---|---|
| **Microsoft Store / MSIX** | Да, сразу — Microsoft переподписывает пакет своим доверием | Если готовы публиковаться в Store. Самый надёжный путь |
| **OV-сертификат** (обычный code signing) от УЦ | Через недели / сотни чистых скачиваний | Основной путь для распространения вне Store. ~$100–200/год |
| **Trusted Signing** (бывш. Azure Code Signing) | Копит репутацию как OV, но подпись дешёвая (~$10/мес) и удобная для CI | С апреля 2025 только организации США/Канады/ЕС/Британии; физлица — только США/Канада |
| **EV-сертификат** | С 2024 — как OV, мгновенного преимущества нет | Не стоит переплаты ради снятия предупреждения |
| **Самоподписанный** | Нет (у чужих людей доверия нет) | Только свои машины и проверка сборки |

Репутация SmartScreen привязана к сертификату: после смены сертификата она копится заново.
У **продлённого** сертификата репутация нарастает заметно быстрее — иногда за несколько дней или
пару сотен чистых скачиваний.

## Что реально ускоряет накопление репутации

1. **Подписывать всё одним именем** — EXE, все библиотеки, установщик, апдейтер; один и тот же
   Subject во всех выпусках. Скрипт сборки так и делает.
2. **Метка времени RFC 3161** на каждой подписи — уже в скрипте.
3. **Распространять с одного стабильного адреса** (страница GitHub Releases подходит).
4. **Отправить билд на ручную проверку Microsoft** как разработчик, при ложном срабатывании:
   [Submit a file for malware analysis](https://www.microsoft.com/en-us/wdsi/filesubmission). Иногда
   снимает блок с конкретного файла быстрее, чем органика.

## Что не работает

- Покупка EV «ради мгновенного обхода» — с 2024 эффекта нет.
- Подпись только установщика без библиотек и апдейтера.
- HTTPS или ZIP «как защита» — SmartScreen смотрит на репутацию хеша, а не на канал доставки.
- Самоподписанный сертификат для публичных пользователей.

## Как собрать подписанный выпуск

Trusted Signing (нужен вход в Azure — `az login` или переменные окружения службы):

```powershell
.\scripts\build-release.ps1 -Version 1.5.0 `
  -TrustedSigningEndpoint https://eus.codesigning.azure.net `
  -TrustedSigningAccount <имя-аккаунта> `
  -TrustedSigningProfile <имя-профиля> `
  -RequireSignature
```

PFX-файл от удостоверяющего центра:

```powershell
.\scripts\build-release.ps1 -Version 1.5.0 -CertificatePath .\signing.pfx -CertificatePassword '<пароль>' -RequireSignature
```

Сертификат на аппаратном токене (EV) — по отпечатку из хранилища Windows:

```powershell
.\scripts\build-release.ps1 -Version 1.5.0 -CertificateThumbprint <отпечаток> -RequireSignature
```

Подписываются `MasterDocumentation.exe`, наши библиотеки внутри портативной сборки и установщик
(уже вместе с вшитым дистрибутивом). Ключ `-RequireSignature` прерывает сборку, если подписать не
удалось. Сам ZIP не подписывается — формат этого не поддерживает, поэтому подписаны файлы внутри
него. Помните: снятие предупреждения даёт не сам факт подписи, а накопленная репутация (см. выше).

## Сборка на GitHub Actions

Секреты репозитория (Settings → Secrets and variables → Actions):

- `SIGNING_CERTIFICATE` — PFX в base64
  (`[Convert]::ToBase64String([IO.File]::ReadAllBytes('signing.pfx'))`), `SIGNING_PASSWORD` — пароль;
- либо `TRUSTED_SIGNING_ENDPOINT`, `TRUSTED_SIGNING_ACCOUNT`, `TRUSTED_SIGNING_PROFILE` вместе с
  учётными данными Azure (`AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_CLIENT_SECRET`).

Без секретов сборка проходит, но файлы остаются неподписанными.

## Проверка перед публикацией

```powershell
Get-AuthenticodeSignature .\artifacts\MasterDocumentation-Setup-v1.5.0.exe | Format-List Status, SignerCertificate, TimeStamperCertificate
```

`Status` должен быть `Valid`, у сертификата — алгоритм RSA и непустая метка времени. То же делает
`signtool verify /pa /v <файл>`.

## Самоподписанный сертификат: для чего он и для чего нет

```powershell
.\scripts\new-signing-certificate.ps1 -Subject 'CN=Название организации' -OutputPath .\artifacts\test-signing.pfx -Password '<пароль>'
```

Скрипт создаёт RSA-3072 сертификат подписи кода, экспортирует `.pfx` (для подписи) и `.cer` (для
раздачи доверия). Он нужен, чтобы:

- проверить, что подпись правильно встраивается в EXE и установщик;
- раздать доверие **внутри своей организации** — поставить `.cer` в «Доверенные корневые центры
  сертификации» и «Доверенные издатели» на нужных компьютерах вручную, групповой политикой или
  ключом `-InstallToTrustedRoot` (меняет доверие всей системы, применяйте осознанно).

Публичным пользователям он предупреждение **не** убирает — им ваш корень не доверен.

При локальной проверке учтите: у файла, собранного на этой же машине, нет метки Mark-of-the-Web,
и SmartScreen для него не срабатывает в принципе. Чтобы увидеть настоящее поведение, скачайте файл
из интернета (например, из выпуска на GitHub).
